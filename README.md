# Liquid Gradient Tool

Инструмент для создания анимированных «жидких» градиентов (liquid /
mesh gradients) с бесшовным зацикливанием и экспортом в **WebM (VP9)**,
**MP4 (H.264)** и **GIF** — специально для фоновых видео в hero-секциях
сайтов.

Работает полностью в браузере, без сервера и сборки: WebGL2-шейдер
рисует поток на canvas, а экспорт кодирует кадры прямо на клиенте.

## Как это устроено

- **Рендер** — `src/render/shaders.js` + `LiquidGradientRenderer.js`.
  Цветовое поле строится через доменный варпинг (domain warping,
  техника Иньиго Килеса) поверх 4D simplex-шума.
- **Бесшовный loop** — время анимации подаётся в шум не как обычная
  прямая, а как обход по окружности в 3-м/4-м измерении шума
  (`vec4(x, y, cos(θ), sin(θ))`). При θ = 2π это ровно та же точка,
  что при θ = 0 — поэтому последний кадр и первый кадр экспортируемого
  ролика стыкуются без видимого скачка. Источник 4D simplex noise —
  реализация Ashima Arts / Stefan Gustavson (`webgl-noise`, MIT),
  подключена локально в `vendor/webgl-noise/` (пакет `glsl-noise`
  с npm, без обращения к CDN в рантайме).
- **Экспорт WebM и MP4** — `src/export/exportVideo.js`. Кадры
  рендерятся по одному и кодируются WebCodecs `VideoEncoder` (VP9 для
  WebM, H.264 High profile для MP4) с заданным битрейтом и
  `alpha: 'discard'`, а затем упаковываются вендоренными муксерами
  [`webm-muxer`](https://www.npmjs.com/package/webm-muxer) и
  [`mp4-muxer`](https://www.npmjs.com/package/mp4-muxer) (MIT,
  `vendor/`). Время кадров берётся из номера кадра, а не из часов,
  поэтому экспорт не привязан к реальному времени, а длительность файла
  точная. MP4 пишется с `moov` в начале файла, чтобы видео начинало
  играть до полной загрузки.
- **WebM с альфа-каналом** — `src/export/exportWebm.js`, только если
  снять галочку «Убрать из WebM». Этот путь использует `MediaRecorder`:
  Chrome при записи canvas добавляет в VP9 альфа-канал (в заголовке
  дорожки `AlphaMode = 1`), даже когда картинка непрозрачная. Запись идёт
  в реальном времени.
- **Экспорт GIF** — `src/export/exportGif.js` поверх библиотеки
  [`gif.js`](https://www.npmjs.com/package/gif.js) (MIT), вендоренной
  в `vendor/gifjs/` (`gif.js` + воркер `gif.worker.js`) — тоже без
  внешних CDN-запросов.

## Запуск

Нужен локальный HTTP-сервер (не `file://`) — GIF-экспорт использует
Web Worker, а браузеры блокируют воркеры для файлов, открытых напрямую
с диска.

```bash
# любой статический сервер подойдёт, например:
npx serve .
# или
python3 -m http.server 8080
```

Откройте `http://localhost:PORT/` в Chrome или Edge (нужны WebGL2 и
WebCodecs). Для MP4 нужен встроенный в браузер кодировщик H.264: он есть
в Chrome, Edge и Safari, но отсутствует в сборках Chromium без
проприетарных кодеков — там инструмент честно сообщит, что MP4 создать
нельзя, а WebM всё равно сохранит.

## Использование

Слева — внешний вид градиента, в центре — превью, справа — всё, что
относится к файлу на выходе (размер, длина цикла, FPS, экспорт); под
ними — отрендеренные варианты. Интерфейс рассчитан на экран 1920×1080;
на мониторах больше (2K, 4K) он пропорционально увеличивается. Работает
только на компьютере: на телефонах и планшетах вместо инструмента
показывается сообщение.

1. Выберите пресет (кнопка «▾» в заголовке «Цвета» раскрывает список,
   активный подсвечивается) или задайте свои цвета
   (2–6) — кликом по свотчу или вводом HEX в поле рядом (с `#` или без,
   3- или 6-значный формат, например `f0a` или `#ff00aa`; невалидное
   значение откатывается при потере фокуса). Перетаскивайте цвета за
   ручку «⠿» — порядок в списке задаёт порядок цветов в градиенте.
   Кнопки ↶ / ↷ в заголовке секции (или Ctrl+Z / Ctrl+Shift+Z вне
   текстовых полей) отменяют и повторяют любые правки палитры.
2. Настройте «Форму потока»: масштаб узора, искажение, баланс цветов
   (сдвигает градиент к первым или к последним цветам списка) и
   скорость движения (0% — почти неподвижный узор). «↻ Новый узор»
   меняет рисунок, сохраняя характер движения. Двойной клик по
   ползунку возвращает значение по умолчанию.
3. По желанию включите «Зерно» — анимированное зерно поверх
   градиента, которое меняется каждый кадр, как плёнка; цикл при этом
   остаётся бесшовным. Параметры:
   - **размер** — 1–8 px итогового файла; 1 px — классическое зерно,
     крупнее — круглые точки;
   - **плотность** — доля заполненных ячеек;
   - **непрозрачность**;
   - **разброс яркости** — 0% — все зёрна одного цвета, 100% — у
     каждого зерна своя яркость от чёрного до выбранного цвета;
   - **мягкость края** — от чётких точек до размытых (для размера от
     2 px);
   - **режим наложения** — «Обычный» (зерно поверх цвета),
     «Перекрытие» и «Мягкий свет» (формулы W3C Compositing and
     Blending): светлые зёрна осветляют, тёмные затемняют, а
     серые 50% ничего не меняют — вместе с разбросом яркости это даёт
     фотографический шум;
   - **цвет** — свотч или HEX.

   Анимированный шум сжимается хуже всего остального: при низком
   битрейте он превращается в «кашу» — поднимайте битрейт видео.
4. Справа выберите формат:
   - **WebM + MP4** (по умолчанию) — два файла для сайта: WebM (VP9)
     как основной и MP4 (H.264) как запасной для Safari;
   - **WebM (VP9)** или **MP4 (H.264)** по отдельности;
   - **GIF** — для превью (256 цветов, файл тяжелее).
5. Задайте ширину × высоту (округляются до чётных), длину цикла
   (1–10 с) и FPS. Для видео — **битрейт**
   (по умолчанию 1,5 Мбит/с; для плавного градиента обычно хватает
   1–2 Мбит/с, выше — если на резких переходах цвета видны полосы или
   блоки). Для WebM — галочка **«Убрать из WebM»** (альфа-канал; включена
   по умолчанию). В MP4 (H.264) и GIF альфа-канала нет в любом случае.
6. На кнопке экспорта видно итог: размер, длительность, FPS и примерный
   вес файла (битрейт × длительность). Готовые файлы появляются в ленте
   «Отрендеренные варианты» внизу с кнопкой «Скачать».

## Встраивание в hero-секцию

### WebM + MP4 (рекомендуется)

Браузер берёт первый `<source>`, который умеет воспроизвести: WebM —
основной, MP4 — запасной (Safari).

```html
<div class="hero">
  <video class="hero-bg" autoplay muted loop playsinline>
    <source src="liquid-gradient-1920x1080.webm" type="video/webm" />
    <source src="liquid-gradient-1920x1080.mp4" type="video/mp4" />
  </video>
  <div class="hero-content">…</div>
</div>
```

```css
.hero { position: relative; overflow: hidden; }
.hero-bg {
  position: absolute;
  inset: 0;
  width: 100%;
  height: 100%;
  object-fit: cover;
  z-index: -1;
}
```

`autoplay` в браузерах работает надёжно только вместе с `muted` —
атрибут `muted` обязателен, у видео и так нет звуковой дорожки.

### GIF

```html
<div class="hero" style="background-image: url('liquid-gradient-480x270.gif'); background-size: cover;">
  …
</div>
```

## Известные ограничения

- GIF ограничен 256 цветами на кадр — на плавных градиентах возможен
  лёгкий бандинг; используйте GIF для небольших превью, а не для
  полноразмерного hero-фона.
- MP4 (H.264) зависит от кодировщика в браузере. Экспорт MP4 не
  проверялся в песочнице разработки (там Chromium без H.264): проверена
  вся цепочка MP4-упаковки с подставленным VP9 и сообщение об
  отсутствии кодировщика. Первый реальный H.264-экспорт стоит проверить
  в Chrome, Edge или Safari.
- WebM с альфа-каналом (галочка снята) записывается в реальном времени
  через `MediaRecorder`: если компьютер не успевает рендерить кадры в
  реальном времени, видео получится длиннее и медленнее. Остальные
  форматы от скорости рендера не зависят.
- Размер своего кадра округляется до чётных чисел — H.264 не принимает
  нечётные ширину и высоту.
- Размер зерна задан в пикселях итогового файла. GIF рендерится в
  меньшем размере (по «Ширине GIF»), поэтому относительно кадра зерно в
  нём крупнее, чем в видео.
