# Liquid Gradient Tool

Инструмент для создания анимированных «жидких» градиентов (liquid /
mesh gradients) с бесшовным зацикливанием и экспортом в **WebM** и
**GIF** — специально для фоновых видео в hero-секциях сайтов.

Работает полностью в браузере, без сервера и сборки: WebGL2-шейдер
рисует поток на canvas, а экспорт кодирует кадры прямо на клиенте.

## Как это устроено

- **Рендер** — `src/render/shaders.js` + `LiquidGradientRenderer.js`.
  Цветовое поле строится через доменный варпинг (domain warping,
  техника Иньиго Килеса) поверх 4D simplex-шума.
- **Бесшовный loop** — время анимации подаётся в шум не как обычная
  прямая, а как обход по окружности в 3-м/4-м измерении шума
  (`vec4(x, y, cos(θ), sin(θ))`). При θ = 2π это ровно та же точка,
  что при θ = 0 — поэтому последний кадр и первый кадр экспортируемого
  ролика стыкуются без видимого скачка. Источник 4D simplex noise —
  реализация Ashima Arts / Stefan Gustavson (`webgl-noise`, MIT),
  подключена локально в `vendor/webgl-noise/` (пакет `glsl-noise`
  с npm, без обращения к CDN в рантайме).
- **Экспорт WebM** — `src/export/exportWebm.js`. Кадры рендерятся
  строго по одному через `canvas.captureStream(0)` (ручной режим) +
  `track.requestFrame()`, поэтому в файл попадает каждый кадр ровно
  один раз, без пропусков/дублей от реального времени кадра.
- **Экспорт GIF** — `src/export/exportGif.js` поверх библиотеки
  [`gif.js`](https://www.npmjs.com/package/gif.js) (MIT), вендоренной
  в `vendor/gifjs/` (`gif.js` + воркер `gif.worker.js`) — тоже без
  внешних CDN-запросов.

## Запуск

Нужен локальный HTTP-сервер (не `file://`) — GIF-экспорт использует
Web Worker, а браузеры блокируют воркеры для файлов, открытых напрямую
с диска.

```bash
# любой статический сервер подойдёт, например:
npx serve .
# или
python3 -m http.server 8080
```

Откройте `http://localhost:PORT/` в Chrome/Edge (нужен WebGL2 и
`MediaRecorder` с поддержкой `video/webm`).

## Использование

Слева — внешний вид градиента, справа — превью и всё, что относится к
файлу на выходе (размер, длительность, FPS, кнопки экспорта). На
телефоне превью закреплено сверху, настройки прокручиваются под ним.

1. Выберите пресет (активный подсвечивается) или задайте свои цвета
   (2–6) — кликом по свотчу или вводом HEX в поле рядом (с `#` или без,
   3- или 6-значный формат, например `f0a` или `#ff00aa`; невалидное
   значение откатывается при потере фокуса). Перетаскивайте цвета за
   ручку «⠿» — порядок в списке задаёт порядок цветов в градиенте.
   Кнопки ↶ / ↷ в заголовке секции (или Ctrl+Z / Ctrl+Shift+Z вне
   текстовых полей) отменяют и повторяют любые правки палитры.
2. Настройте «Форму потока»: масштаб узора, искажение, баланс цветов
   (сдвигает градиент к первым или к последним цветам списка) и
   скорость движения (0% — почти неподвижный узор). «↻ Новый узор»
   меняет рисунок, сохраняя характер движения. Двойной клик по
   ползунку возвращает значение по умолчанию.
3. Справа выберите размер, длительность loop, FPS и ширину GIF — итоговые
   параметры каждого файла написаны прямо на кнопках экспорта.
4. Нажмите «Экспорт WebM» (для продакшн-видео на сайте) или «Экспорт
   GIF» (для превью — качество ниже из-за 256-цветной палитры GIF).
   Готовые файлы появляются под панелью экспорта с кнопкой «Скачать».

## Встраивание в hero-секцию

### WebM (рекомендуется)

```html
<div class="hero">
  <video
    class="hero-bg"
    src="liquid-gradient-1920x1080.webm"
    autoplay
    muted
    loop
    playsinline
  ></video>
  <div class="hero-content">…</div>
</div>
```

```css
.hero { position: relative; overflow: hidden; }
.hero-bg {
  position: absolute;
  inset: 0;
  width: 100%;
  height: 100%;
  object-fit: cover;
  z-index: -1;
}
```

`autoplay` в браузерах работает надёжно только вместе с `muted` —
атрибут `muted` обязателен, у видео и так нет звуковой дорожки.

### GIF

```html
<div class="hero" style="background-image: url('liquid-gradient-480x270.gif'); background-size: cover;">
  …
</div>
```

## Известные ограничения

- GIF ограничен 256 цветами на кадр — на плавных градиентах возможен
  лёгкий бандинг; используйте GIF для небольших превью, а не для
  полноразмерного hero-фона.
- Экспорт WebM идёт в реальном времени (запись Nс занимает ≈Nс),
  экспорт GIF — быстрее реального времени, но кодирование само по
  себе не мгновенное на больших разрешениях/длительностях.
- Проверено в Chromium; Safari на момент написания не полностью
  поддерживает `MediaRecorder` с `video/webm` — для него используйте
  GIF или конвертируйте WebM в MP4/H.264 отдельно (например, ffmpeg).
